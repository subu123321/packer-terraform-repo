# Image Factory: two pipelines

## What the golden images contain (built by Packer)
| Image | Base | Preinstalled |
|---|---|---|
| `windows-2025` | Windows Server 2025 Datacenter (Gen2) | **IIS**, **Git**, **Google Chrome** |
| `ubuntu-2404` | Ubuntu 24.04 LTS (Gen2) | **Git**, **Python 3** (pip, venv), **Docker Engine** (compose, buildx) |

The build itself verifies every tool and fails if one is missing. The customization lives in
`packer/scripts/windows-setup.ps1` and `packer/scripts/ubuntu-setup.sh`.

### Demo checklist: prove it to your manager
- **Ubuntu:** `ssh labadmin@<ip>` shows a banner listing the tool versions. Then `git --version`, `python3 --version`, `sudo docker run --rm hello-world`.
  (`/etc/image-info.txt` has the same manifest. Use `sudo docker`, or run `sudo usermod -aG docker $USER` and log in again.)
- **Windows:** browse to `http://<ip>` (the IIS page lists IIS, Git and Chrome versions), or RDP in and open Chrome, run `git --version` in PowerShell,
  and read `C:\ProgramData\image-info\installed-tools.txt`.
- **Azure portal:** Compute Gallery > image definition > version > Tags shows `tools=...` and the version.


| Pipeline | File | When to run |
|---|---|---|
| **1 - Build images** | `pipelines/1-build-images.yml` | Once, or whenever you want a new image version |
| **2 - Deploy VMs** | `pipelines/2-deploy-vms.yml` | Any number of times |

## One-time prerequisites
1. Service connection: Project settings > Service connections > New > Azure Resource Manager
   (service principal, automatic), scope **Subscription**, named `azure-sub-conn`, with **Contributor**.
2. Push this repo and create both pipelines (New pipeline > Existing YAML).

## Pipeline 1 (run once)
Bootstraps Azure (RGs, gallery, image definitions, Terraform state storage, provider registration) and builds the images.
Options: tick or untick **Ubuntu** and **Windows**. Expect about 15-20 min for Ubuntu and 30-45 min for Windows, in parallel.

## Pipeline 2 (run repeatedly), all set as run-time options
| Option | Meaning |
|---|---|
| Action = `create` | Create or update VMs to match the counts. Raising or lowering a count adds or removes VMs. |
| Action = `destroy-vms` | Delete all VMs and their network. Keeps gallery, images and state storage, so you can re-create quickly. |
| Action = `destroy-everything` | Delete VMs **and** gallery, images and state storage. Run pipeline 1 again afterwards to rebuild. |
| Number of Ubuntu / Windows VMs | 0 to 5 each. `0` skips that OS. At least one must be above 0 for `create`. |
| VM size | e.g. `Standard_D2s_v3` |
| Image version | `latest` or a specific one such as `1.0.123` |
| Allowed source IP | Your public IP/32 for SSH/RDP/HTTP, or `*` for anywhere (not recommended) |

Examples: only 2 Windows VMs = Ubuntu 0, Windows 2. A mixed lab = Ubuntu 2, Windows 1.

After `create`, the Apply log prints each VM's IP, URL, SSH/RDP hint and the generated login.
The Apply stage uses the environment `image-lab`. Add an approval on it for a manual gate.

## Notes
- The state storage account name is derived from the subscription id, so both pipelines find it without copying values.
- The admin password is generated by Terraform and is also in the state and plan artifact (lab only).
  For real use, switch to Key Vault and SSH keys.
- Keep the `variables:` blocks in both pipeline files in sync (location, gallery and state names).
